End-to-end flow on submit (worktree opted in)

1. Client POSTs RPC createIssue with {title, body, labels, assignees, repoRef}.
2. Server resolves GitHub provider → gh issue create → parses returned issue number.
3. If worktree.enabled in payload: server calls git.createWorktreeForProject({intent:{kind:"issue",number,branchName?}}). Branch name was already generated client-side via generateBranchName.
4. Response = {issue: SourceControlIssueSummary, worktree?: GitCreateWorktreeForProjectOutput}. Client invalidates the issues list query, selects the new issue in IssueDetail, opens the worktree if present.

AI generation flow (button clicks)

Polish body: client → generateIssueContent({mode:"polish", rough, currentTitle?}) → server uses textGenerationModelSelection from settings → returns {title?, body} → client replaces textarea content.
Suggest title: same endpoint with mode:"title", input is the current body. Returns {title}.
Regenerate branch: reuses existing generateBranchName with the current title+body as message.
